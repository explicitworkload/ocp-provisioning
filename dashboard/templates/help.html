OVERVIEW

This dashboard provides self-service controls for demonstrating OpenShift Service Mesh 3 capabilities using the Bookinfo sample application. The Bookinfo app consists of four microservices:

  • productpage — the frontend, calls details and reviews
  • details — book details
  • reviews — book reviews (3 versions: v1 = no stars, v2 = black stars, v3 = red stars)
  • ratings — star ratings, called by reviews v2 and v3

All services run with Istio sidecar proxies that intercept traffic. The controls below let you manipulate how traffic flows through the mesh without modifying any application code.

TRAFFIC GENERATOR

Burst Mode

Sends a fixed number of HTTP requests to the Bookinfo productpage. Use this to quickly populate the Kiali traffic graph.

Requests Number of requests to send (1 – 10,000)
Concurrency Parallel threads (1 – 50). Higher = faster completion

Sustained Mode

Sends continuous traffic for a set duration. Ideal for keeping the Kiali graph active during a live demo, or for observing the effect of mesh policies over time.

Duration How long to run, in minutes (1 – 60)
Concurrency Parallel threads. Controls request rate
Stop Ends sustained traffic early
Demo tip: Start 15 min sustained traffic at concurrency 10, then switch to the Kiali Traffic Graph to show a live service map with request rates, latency, and success rates on each edge.

TRAFFIC SHIFTING

Controls what percentage of traffic goes to each version of the reviews service. This is how you do canary deployments or A/B testing with a service mesh — no redeployment needed.

v1 / v2 / v3 Weight percentages. Must sum to 100%

Under the hood, this creates an Istio VirtualService with weighted routes and a DestinationRule with subsets for each version.

Demo scenario: Start with v1=100 (no stars shown). Then shift to v1=50, v3=50. Refresh the Bookinfo page multiple times — you'll see it alternate between no stars and red stars. Kiali graph will show the split visually.

FAULT INJECTION

Injects failures into the ratings service to test how the application handles errors — without modifying any code or crashing any pods.

Delay Mode

Adds artificial latency to responses from ratings. Reviews v2 and v3 call ratings, so they'll slow down. Reviews v1 doesn't call ratings, so it's unaffected.

Delay (ms) Latency to add (e.g., 5000 = 5 seconds)
% Percentage of requests affected (100% = all requests)

Abort Mode

Returns an HTTP error code instead of a real response. Simulates a service outage.

HTTP Status Error code to return (e.g., 500, 503)
% Percentage of requests affected
Demo scenario: Inject a 5s delay at 100%. Open Bookinfo — the page loads slowly because reviews is waiting on ratings. Then show Kiali — the edge from reviews to ratings will show high latency (red). Reset and inject an HTTP 503 abort — now reviews shows "Ratings service is currently unavailable" in the UI, and Kiali shows 5xx errors on the ratings edge.

CIRCUIT BREAKER

Limits the number of connections and requests to the reviews service. When limits are exceeded, the mesh rejects additional requests immediately (HTTP 503) instead of queuing them — preventing cascading failures.

Max Conn Maximum TCP connections allowed
Pending Maximum queued requests waiting for a connection
Requests Maximum concurrent HTTP requests

Also enables outlier detection: if a reviews pod returns consecutive 5xx errors, it's temporarily ejected from the load-balancing pool.

Demo scenario: Set all limits to 1, then launch burst traffic with concurrency 20. Many requests will fail with 503 because the circuit breaker trips. Show the increased error rate in Kiali. Then increase limits to 50 and re-run — all requests succeed.

REQUEST TIMEOUT & RETRIES

Sets a maximum wait time and automatic retries for requests to the reviews service.

Timeout Max time to wait for a response (e.g., "3s", "500ms")
Retries Number of automatic retry attempts on failure
Per Try Timeout for each individual retry attempt
Demo scenario: First, inject a 5s delay on ratings. Then set a 1s timeout on reviews with 2 retries. Now Bookinfo loads fast (doesn't hang for 5s) because the timeout kicks in and reviews returns without waiting for ratings. Kiali will show the timeout errors and retry attempts on the graph edges.

PLATFORM ADMIN

The Platform page lets you scale worker and GPU MachineSets up or down, and view the current node status. Use the Shutdown All Workers button to scale all worker and GPU MachineSets to 0 replicas.

Scale Set the desired replica count for each MachineSet (0 – 10)
Refresh Reload current node and MachineSet status
Shutdown Scales all non-master MachineSets to 0 (requires confirmation)
Demo tip: Use the Platform page to scale GPU MachineSets from 0 to 1 during a live demo to show on-demand GPU provisioning. New nodes take 5–10 minutes to become Ready.

RESET ALL

The Reset All Mesh Policies button at the bottom of the Service Mesh Controls section removes all VirtualServices and DestinationRules created by this dashboard, returning the mesh to its default round-robin behaviour. Each card also has its own individual Reset button.

COMPANION TOOLS

  • Kiali — Service mesh observability. Use the Traffic Graph tab to visualise traffic flow, latency, and error rates in real time.
  • Bookinfo — The sample application. Open it in a browser and refresh to see the effects of traffic shifting and fault injection.
  • Gatus — Health monitoring dashboard showing the status of all cluster services.
  • OpenShift Console — Cluster management UI with Network Observability and ODF storage views.
